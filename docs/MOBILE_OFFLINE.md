# Mobile offline workspace

Android downloads a workspace after the first connected sign-in. Later launches open that copy immediately while checking connectivity in the background. Connection/DNS failures do not clear login. Saved native sessions last one year and renew when used near expiry; logout/revocation and security-related sign-in failures remain authoritative. Browser login durations are unchanged. Users who explicitly decline remembered login still need to sign in after ending that temporary session.

Core task creation, title/stage/priority/date/financial edits, completion, project/goal links, project/goal creation and editing, task storage changes, and Focus start/pause/resume/break/stop/explicit completion write to a durable local outbox before being acknowledged. An offline start never marks a task Done. Existing repeating occurrences keep their identities; changing a recurrence schedule still requires a connection. AI, chats, new file downloads, team permissions, milestones and other uncached advanced requests require connectivity. Reports display previously downloaded data until sync; they never fabricate offline totals.

Android stores the workspace and outbox as an AES-GCM encrypted, atomically replaced app-private file backed by Android Keystore. `allowBackup=false` keeps it out of platform backup. Browser mobile sessions use IndexedDB and the normal cookie; they are not an installable offline web shell. No password is stored. Storage failures reject the save rather than showing false success. Account caches and queues are keyed by server workspace/user identity; switching accounts does not replay one account's queue into another. Explicit logout requires pending changes to sync first and removes the current account's active offline data.

Online reconnection, app resume and the foreground refresh replay the outbox in order. `/api/mobile-sync` reuses the existing permission, feature and optimistic-revision checks inside a database transaction. Command UUIDs and payload hashes make response-loss retries idempotent. Local project/task/focus IDs map to returned server IDs before dependent commands replay. A server identity check precedes queue replay. Every command is reauthorised; cached permissions never grant server access.

The transaction-local `humeto_action_time()` defaults to real database time. Only sync sets a bounded recorded action time, so task completion dates, focus events and work intervals reflect the offline action rather than reconnection time. No prior history is rewritten. Session revisions and active-focus checks prevent silently replacing another device's timer. Future/impossibly old timestamps and overlapping changes require review.

A conflict pauses replay and keeps the local queue. Task/plan edits can be explicitly reapplied against the current revision after showing the current server version. Focus/permission conflicts are not force-merged. Choosing the server version requires explicit acknowledgement for the whole pending queue; a local recovery copy remains available in Offline data & sync. A genuine 401 locks cached access while preserving the encrypted work for reauthentication. Login failures do not delete pending edits.

Limits: the first login/download needs internet; only previously fetched reports/details are available; the outbox is capped at 1,000 changes and the Android file at 12 million characters. Normal task creation remains subject to server validation on sync. Offline edits can therefore need correction/review. Device loss, uninstall or clearing app data removes unsynced data; install APK updates over the existing app to retain it. No background internet or cross-device push guarantee is made while the OS has stopped the app.

Migration 037 adds sync receipts and a transaction-local action clock, and updates new-event time defaults/trigger clocks. It changes no existing task or history rows. Account deletion/export operations must also cover `mobile_sync_commands`; local data disappears when the app data is removed. Manual account erasure and other existing Play launch gates remain open.

Validation uses disposable PostgreSQL data: offline restart, task/project linkage, focus pause/restart and completion, reconnection exactly once, DNS fallback, and explicit conflict resolution. Backend checks cover replay/hash mismatch, tenant/user isolation, revisions, measured intervals, session renewal and revocation. Native acceptance checks additionally inspect encrypted storage and saved login. Real-device and iPhone verification are separate from emulator/browser checks.
