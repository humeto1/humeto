# Task search and creating from a search

Web and mobile Tasks and Focus use `shared/task-search.ts`. Search normalizes case, accents and punctuation; matches keywords in any order; handles word prefixes, plurals, a reviewed small synonym map, and one typo for words of 4–6 characters or up to two for longer words. Adjacent transpositions count as one typo. Numbers are exact so a year or reference number is not silently treated as a typo. Task titles/current operation aliases, projects, categories, assignees and supplied goals are searchable. Stronger title matches sort first in the main task views.

Every meaningful keyword must match for an ordinary result. Creation checks also show conservative title overlap suggestions when two or more keywords overlap. This is lexical matching, not an external AI/semantic embedding service, and it cannot guarantee that differently described work is identical.

When a search has no visible results (minimum two characters), `TaskSearchFeedback` checks all tasks already available to that client, including completed/filtered-out tasks, plus the existing permitted Archive/Bin endpoint. It shows the closest five suggestions with Open or Restore. Checks are debounced and stale responses ignored. If candidates exist, or the storage check fails, adding from search requires acknowledging that this is a separate task. The button opens a prefilled creation form; it never writes a task automatically. The form repeats the similarity warning as the title changes. Normal explicit creation remains possible for intentionally separate work or recurring occurrences.

Visibility follows existing backend permissions. The storage endpoint returns up to 1,000 retained stored items; deleted/expired Bin records and inaccessible records cannot be compared. Checks are advisory, not a database uniqueness constraint: simultaneous creation and synonyms outside the reviewed map can still produce duplicates. No schema or production data migration is involved.

Validation: production web/mobile compilation; unit examples for reordered words, typos, accents, synonyms, non-Latin text, aliases, unrelated terms and numeric differences; isolated browser flows for search-to-create, no auto-save, Archive restoration, Bin and completed suggestions, and storage failure. Existing mobile UI, financial/filter, Focus and voice/keyboard flows are also checked. Android testing APK is published through the usual release command; iPhone/real-device testing remains deferred.
